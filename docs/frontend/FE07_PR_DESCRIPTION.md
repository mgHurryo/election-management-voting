# feat(frontend): complete voter roll and results workflows

## 修改目标

补齐 master 的名册与结果占位页，让管理员维护草稿资格、查看关闭后的计票并确认发布，让选民查看已发布结果。复用参考 HTML 和 master 已有视觉规范。

## 修改内容

- 新增 `VoterRollPage` / `useVoterRoll`：分页、BIGINT 字符串 ID、草稿期增删、删除确认、只读状态、失败后刷新核实。
- 新增 `ElectionResultsPage` / `useElectionResults`：关闭后读取、管理员未发布预览、发布确认、选民已发布结果、服务端胜出者与零票候选人展示。
- 复用现有 API、权限守卫、错误处理、设计 token；提取现有正整数 BIGINT 校验，保持创建页行为兼容。
- 增加两页独立样式、键盘焦点恢复、单元回归与四种宽度的浏览器测试；更新旧导航测试。
- `FE07_PROGRESS.md` 记录全部 23 个远端分支、master 功能现状、设计依据与后端交接限制。

## 不包含的内容

不修改后端、数据库、依赖、权限门禁、已有 master 页面视觉；不合并远端后端分支；不增加注册、用户搜索、导入、配额编辑、实时票数、导出、自动破同票或新投票规则。另一 agent 的后端修改不进入本前端提交。

## 风险等级

中：新增业务读写界面；使用既有 API 契约，后端仍须执行最终权限和事务校验。真实后端联调未验证。

## 行为变化

- ADMIN 可读取任意状态名册，只在 DRAFT 增删；失败的写入必须刷新核实后才再次允许修改。
- 结果在 CLOSED 才请求；USER 只显示已发布结果，ADMIN 可预览并明确确认发布。
- 发布请求无计票数据/赢家/时间参数，不自动重试；失败后通过读取核实。
- 名册不显示个人投票历史，结果只显示聚合计票；BIGINT ID 始终以字符串传递。

## 验证方式

在 `frontend` 执行 `npm run typecheck`、`npm run lint`、`npm test`、`npm run test:e2e`、`npm run test:design-reference`、`npm run format:check`、`npm run build`。浏览器验证 1280/768/390/320px、增删/取消/发布、选民权限、错误与空态、键盘焦点及页面横向溢出。测试使用拦截接口，不发送真实投票或发布请求。最终执行结果见 Local 工作日志；CI 在提交 PR 后独立运行。

2026-10-20 本地结果：126 项测试、14 项 Chromium 工作流、参考 HTML 四种宽度检查、typecheck、零警告 lint、格式检查及生产构建均通过。CI/Qodana 与真实后端端到端联调未验证。

## 性能 / 成本影响

无新增依赖、轮询或自动重试。页面按路由懒加载；每次名册页加载读取一次选举和一页名册，结果页先读选举，再按状态和角色读取一次结果。刷新仅由用户触发。

## 安全影响

延续 ADMIN 名册守卫及登录结果守卫；服务端权限不可被 UI 替代。无 Secret、投票选择存储或日志、用户历史曝光或权限扩张。发布确认说明所有有效选民账号的可见性。真实后端授权与匿名事务保证未验证。

## 发布方式

任务分支 PR → master，全部 Build/Test/静态分析等必需门禁通过后由人工决定合并；后续 master → release 仍须完整门禁。不得自动合并或直接发布。发布类别 MINOR，本任务不创建 tag 或修改版本号。

## 回滚方式

仅 revert 本前端功能提交，恢复两个占位路由；不回滚另一 agent 的后端提交。没有数据库迁移、数据删除或补偿操作。
